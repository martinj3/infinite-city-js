COMPACT CONTEXT — Infinite City JS Driving Game
================================================

## Project
Multi-file HTML canvas driving game. No external libraries. Player drives a car (red arrowhead) around procedurally generated streets (straight and curved) on a green grass background, rendered in isometric perspective.

User wants prompts.txt updated each turn with their latest prompt.

## File Structure
- `index.html` — minimal HTML shell, loads scripts
- `constants.js` — all constants, angle/math helpers, slot system, arc math
- `streets.js` — map data (nodes/streets), conflict detection, generation logic
- `drawing.js` — all rendering (isometric camera, roads, intersections, player, HUD)
- `buildings.js` — building generation (houses), works entirely in feet, no drawing logic
- `lighting.js` — shared lighting system (light direction, normal computation, HSL shading)
- `buildings.html` — standalone test page for buildings (5x5 grid, isometric renderer)
- `prompts.txt` — running log of user prompts
- `compact.txt` — this file

## Architecture & Units
- ALL internal units are FEET (position, speed in ft/s, dimensions)
- Only converted to pixels at draw time via PX_PER_FT = 2
- Streets can be at ANY angle (not just axis-aligned) thanks to curved roads
- Curved roads are circular arcs; straight roads connect intersections in any direction

## Isometric Rendering
- View is rotated -45° (VIEW_ANGLE = -π/4) with Y-axis compressed by 0.5
- Camera transform: translate(W/2, H/2) → scale(1, 0.5) → rotate(-π/4) → translate(-player*PX)
- Culling bounds use screen diagonal / PX_PER_FT to account for rotated viewport
- For 3D objects (buildings), height (z) goes straight up on screen: screen_y -= wz * PX_PER_FT
- 3D projection function in buildings.html computes this manually per-vertex

## Key Constants
- STREET_WIDTH = 20ft (10ft per lane)
- DEFAULT_BLOCK_LEN = 400ft
- RIGHT_OF_WAY = 170ft (each side of street, reserved for buildings)
- PROXIMITY_THRESHOLD = 50ft, GENERATE_DIST = 30ft
- CURVE_PROB = 0.4, CURVE_ANGLES = [30, 45, 60, 90]°, CURVE_RADII = [400, 800] ft
- ANGLE_TOL = 0.02 rad (~1 degree)

## Data Structures

### Intersections (nodes Map in streets.js)
Key: "x,y" string -> { x, y, ori, roads: { fwd, right, back, left } }
- ori: orientation angle in radians (direction the source street was heading)
- roads values: null=undecided, true=has road, false=no road

### Streets array (streets.js)
{ x1, y1, x2, y2, curve, bounds }
- curve: null | { cx, cy, r, arcS, arcE, ccw }
- bounds: cached { mnx, mxx, mny, mxy } for culling

### Drawables (buildings.js)
{ polys: [ { pts: [{x,y,z}, ...], color: 'hsl(...)' }, ... ] }
- Each polygon has 3-4 3D points and a single base HSL color string
- Lighting/shading applied at draw time, not baked into the color

## Direction/Slot System
- Slots: fwd, right, back, left (relative to intersection orientation)
- SLOT_OFF: fwd=0, right=π/2, back=π, left=-π/2
- Intersections only allow roads at exactly 90° intervals from orientation
- Different grid orientations can coexist (curves create non-axis-aligned intersections)

## Street Generation Logic
1. Triggers when player within GENERATE_DIST of node with null slots
2. For each undecided slot: roll probability (80% fwd, 60% sides)
3. 40% chance try curve first → fallback to straight → fallback to dead end
4. Connecting to existing intersections requires angle match within ANGLE_TOL

## Conflict Detection (checkConflict in streets.js)
- Skips streets connected to the source intersection
- Curved: simplified bounding box of endpoints + RIGHT_OF_WAY padding
- Straight: rotated rectangle ROW check + general segment crossing check

## Building Generation (buildings.js)

### Color System
- HOUSE_COLORS: weighted palette of 22 realistic American house colors
- Categories: whites/off-whites (most common), beiges/tans, grays, browns, blues, brick reds, yellows/creams, dark greens (rare), pinks (rare)
- pickHouseColor(): weighted random selection + small HSL jitter for variety
- Each house gets a single flat color; shading done at draw time via lighting

### House Generation
- generateHouse() → Drawable with 1-3 rectangular prisms
- Main prism: 20-40ft wide, 25-45ft long, ~9ft tall
- Wing prisms: 12-27ft, attached to random side of main prism
- prismsOverlap(a, b): generic axis-aligned prism overlap check (allows touching, rejects interior overlap)
- Wings retry up to 8 placements to avoid overlap; skipped if no valid position found

### makeRectangularPrism(ox, oy, oz, w, l, h, color)
- Returns 5 face polygons (skip bottom): top, north, south, west, east
- All faces get the same base color string
- Vertex winding produces correct outward normals for backface culling and lighting

## Lighting System (lighting.js)
- LIGHT_DIR = normalize(-2, 1, 3) — sun from bottom-left of screen, above
- computeNormal(pts): unit outward normal from polygon vertices via cross product
- applyLighting(hslStr, normal): adjusts HSL lightness by dot(normal, lightDir) * 12, clamped [10%, 95%]
- Produces three distinct brightness levels on visible iso faces: top brightest, left wall medium, right wall darkest

## 3D Rendering (buildings.html)
- project(wx, wy, wz, camX, camY): manual isometric projection matching the driving game's canvas transform, with height going straight up on screen
- Backface culling via screen-space cross product (skip if cross <= 0)
- Depth sorting: avgScreenY + 2*avgZ*PX_PER_FT (compensates for height in screen_y, ensures tops draw after sides)
- Painter's algorithm: sort ascending, draw far-to-near
- Thin dark outlines on faces (rgba(0,0,0,0.3))

### Vertex strategy
All geometry functions create independent vertex objects per face (no sharing). This means in-place transforms (like rotatePolys) are safe without deduplication.

## Road Drawing (drawing.js, layered)
1. Road surfaces + edge lines (straight: rotated rects; curved: arc bands)
2. Intersection squares (rotated by node.ori, covers junctions)
3. Center lane markings (yellow dashed)
4. Player car (red arrowhead)
5. HUD (speed in mph, street count) — drawn in screen space after ctx.restore()

## Player Physics
- Max speed: 150 ft/s, reverse: 30 ft/s
- Accel: 40 ft/s², brake: 60 ft/s², drag: 3 ft/s²
- Turning scales with speed, max turn rate: 3 rad/s

## Known Pitfalls & Past Bugs
- sourceDir → orientation: `ori` IS direction of travel, NOT where source came from
- Grid closure: false directions reset to null when new street connects to fully-resolved node
- Generation is proximity-driven only, never cascading
- Angle matching: findSlot enforces 90° multiples with ANGLE_TOL tolerance
- Shared vertices: never mutate polygon vertex objects; offset at projection time
