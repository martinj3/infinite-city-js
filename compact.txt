COMPACT CONTEXT — Infinite City JS Driving Game
================================================

## Project
Multi-file HTML canvas driving game. No external libraries. Player drives a car (red arrowhead) around procedurally generated streets (straight and curved) on a green grass background, rendered in isometric perspective. Separate test page (buildings.html) for building generation.

User wants prompts.txt updated each turn with their latest prompt.

## File Structure
- `index.html` — driving game HTML shell, loads: constants.js, streets.js, drawing.js, game.js
- `constants.js` — all constants, angle/math helpers, slot system, arc math, isometric view constants
- `streets.js` — map data (nodes/streets), conflict detection, generation logic
- `drawing.js` — 2D road rendering (isometric camera, roads, intersections, player, HUD)
- `buildings.js` — building generation (houses with roofs, doors, windows), drawable tree, rotation helpers
- `lighting.js` — shared lighting system (light direction, normal computation, HSL shading)
- `render3d.js` — shared 3D isometric rendering (projection, backface culling, depth sorting, drawing)
- `buildings.html` — standalone test page for buildings (5x5 grid), loads: constants, buildings, lighting, render3d
- `prompts.txt` — running log of user prompts
- `compact.txt` — this file

## Architecture & Units
- ALL internal units are FEET (position, speed in ft/s, dimensions)
- Only converted to pixels at draw time via PX_PER_FT = 2
- Streets can be at ANY angle (not just axis-aligned) thanks to curved roads
- Curved roads are circular arcs; straight roads connect intersections in any direction

## Isometric Rendering
- View constants in constants.js: VIEW_ANGLE = -π/4 (mutable), Y_SCALE = 0.5 (mutable), ROTATE_SPEED = 1.2 rad/s, TILT_SPEED = 0.4/s
- COS_V/SIN_V replaced with getCosV()/getSinV() functions (recomputed each frame from current VIEW_ANGLE)
- Q/E keys smoothly rotate the view; R/F keys smoothly adjust tilt (Y_SCALE clamped to 0.25–0.75)
- Both controls work in index.html and buildings.html
- 2D roads (drawing.js): canvas transform — translate(W/2,H/2) → scale(1,Y_SCALE) → rotate(VIEW_ANGLE) → translate(-player*PX)
- 3D objects (render3d.js): manual per-vertex projection, height (z) goes straight up on screen
- Backface culling via screen-space cross product (skip if cross <= 0)
- Depth sorting: avgScreenY + 2*avgZ*PX_PER_FT (compensates for height, ensures tops draw after sides)
- Thin dark outlines on faces (rgba(0,0,0,0.3))

## Key Constants
- STREET_WIDTH = 20ft (10ft per lane)
- DEFAULT_BLOCK_LEN = 400ft
- RIGHT_OF_WAY = 170ft (each side of street, reserved for buildings)
- PROXIMITY_THRESHOLD = 50ft, GENERATE_DIST = 30ft
- CURVE_PROB = 0.4, CURVE_ANGLES = [30, 45, 60, 90]°, CURVE_RADII = [400, 800] ft
- ANGLE_TOL = 0.02 rad (~1 degree)

## Data Structures

### Intersections (nodes Map in streets.js)
Key: "x,y" string -> { x, y, ori, roads: { fwd, right, back, left } }
- ori: orientation angle in radians (direction the source street was heading)
- roads values: null=undecided, true=has road, false=no road

### Streets array (streets.js)
{ x1, y1, x2, y2, curve, bounds }
- curve: null | { cx, cy, r, arcS, arcE, ccw }
- bounds: cached { mnx, mxx, mny, mxy } for culling

### Drawable Tree (buildings.js)
{ polys: [{pts, color}, ...], children: [Drawable, ...] }
- Tree structure: root (no polys) → prism children (walls+roof) → detail grandchildren (door, windows)
- Each polygon has 3-4 3D points and a single base HSL color string
- Lighting/shading applied at draw time, not baked into the color
- All geometry functions create independent vertex objects per face (no sharing), so in-place transforms are safe

### Drawable Tree Rendering
- drawDrawableTree(drawable, ox, oy, projectAndDrawFn, depthFn): recursive depth-first drawing
- Each node's own polys are projected, culled, depth-sorted, and drawn first
- Children are sorted by average depth (far-to-near), each drawn completely before the next
- This ensures: details draw after their parent walls; nearer siblings occlude farther siblings' details
- projectAndDrawFn and depthFn are callbacks so different pages can bind their own camera position

## Direction/Slot System
- Slots: fwd, right, back, left (relative to intersection orientation)
- SLOT_OFF: fwd=0, right=π/2, back=π, left=-π/2
- Intersections only allow roads at exactly 90° intervals from orientation
- Different grid orientations can coexist (curves create non-axis-aligned intersections)

## Street Generation Logic
1. Triggers when player within GENERATE_DIST of node with null slots
2. For each undecided slot: roll probability (80% fwd, 60% sides)
3. 40% chance try curve first → fallback to straight → fallback to dead end
4. Connecting to existing intersections requires angle match within ANGLE_TOL

## Conflict Detection (checkConflict in streets.js)
- Skips streets connected to the source intersection
- Curved: simplified bounding box of endpoints + RIGHT_OF_WAY padding
- Straight: rotated rectangle ROW check + general segment crossing check

## Building Generation (buildings.js)

### Color System
- HOUSE_COLORS: weighted palette of 22 realistic American house colors
- Categories: whites/off-whites (most common), beiges/tans, grays, browns, blues, brick reds, yellows/creams, dark greens (rare), pinks (rare)
- pickHouseColor(): weighted random selection + small HSL jitter for variety
- ROOF_COLOR: fixed brown hsl(20, 30%, 35%) — also used for doors
- WINDOW_COLOR: light blue hsl(210, 50%, 75%)

### House Generation
- generateHouse(facingAngle=0) → Drawable tree with 1-3 rectangular prisms
- Main prism: 20-40ft wide, 25-45ft long, ~9ft tall
- Wing prisms: 12-27ft, attached to east/west/south of main prism (north reserved for front door)
- prismsOverlap(a, b): generic axis-aligned prism overlap check
- Wings retry up to 8 placements to avoid overlap

### Roofs
- 50/50 gable vs hip roof, chosen once per house
- Lengthwise orientation (ridge direction) also chosen once per house, applied to all prisms
- makeGableRoof(): two sloped rectangles (ROOF_COLOR) + two triangular gable ends (house color)
- makeHipRoof(): four sloped faces (all ROOF_COLOR), ridge inset from ends; becomes pyramid when cross-dimension >= along-dimension
- Gable/hip height: random 25-60% of cross-dimension

### Doors
- One front door per house, on north face of main prism (before rotation)
- Centered horizontally, ROOF_COLOR, 3-5ft wide, 7-9ft tall
- Tiny epsilon offset (0.05ft) from wall surface
- Wing prisms blocked from north side to keep door unobstructed

### Windows
- generatePrismWindows(ox, oy, w, l, exclusions): generates windows on all 4 walls
- Per-prism random params: window top (7-8ft), height (3-5ft), standard width (3-8ft)
- 25% chance each window varies from standard width (clamped 3-8ft)
- 2ft margin from wall edges, 4ft gap between windows
- Door zone is an exclusion (with 1ft buffer) on the main prism's north wall
- Correct winding per wall face for backface culling

### Rotation
- rotatePolys(polys, angle, cx, cy): rotates vertex x/y in-place around center point
- rotateDrawable(drawable, angle, cx, cy): recursive rotation of entire drawable tree
- generateHouse(facingAngle) rotates all geometry around main prism center after construction
- Buildings test page currently uses Math.PI to face doors toward camera

### makeRectangularPrism(ox, oy, oz, w, l, h, color, includeTop=true)
- Returns 4-5 face polygons (skip bottom; top optional for houses with roofs)
- Independent vertex objects per face (no sharing)
- Vertex winding produces correct outward normals for backface culling and lighting

## Lighting System (lighting.js)
- LIGHT_DIR = normalize(-2, 1, 3) — sun from bottom-left of screen, above
- computeNormal(pts): unit outward normal from polygon vertices via cross product
- applyLighting(hslStr, normal): adjusts HSL lightness by dot(normal, lightDir) * 12, clamped [10%, 95%]

## Road Drawing (drawing.js, layered)
1. Road surfaces + edge lines (straight: rotated rects; curved: arc bands)
2. Intersection squares (rotated by node.ori, covers junctions)
3. Center lane markings (yellow dashed)
4. Player car (red arrowhead)
5. HUD (speed in mph, street count) — drawn in screen space after ctx.restore()

## Player Physics
- Max speed: 150 ft/s, reverse: 30 ft/s
- Accel: 40 ft/s², brake: 60 ft/s², drag: 3 ft/s²
- Turning scales with speed, max turn rate: 3 rad/s

## Known Pitfalls & Past Bugs
- sourceDir → orientation: `ori` IS direction of travel, NOT where source came from
- Grid closure: false directions reset to null when new street connects to fully-resolved node
- Generation is proximity-driven only, never cascading
- Angle matching: findSlot enforces 90° multiples with ANGLE_TOL tolerance
- Vertex duplication: all geometry creates independent vertex objects per face (no sharing), so in-place transforms like rotatePolys are safe without deduplication
- Depth sorting for coplanar details: solved via drawable tree (details as children, depth-first recursive rendering), NOT via zBias thresholds which proved fragile
- BFS layer rendering breaks inter-sibling occlusion; depth-first per-child is correct
